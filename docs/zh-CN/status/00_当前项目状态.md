## 5. Kindle

Kindle 是第一个 Reference Platform Port。

冻结方向：

```text
Client / bootstrap
→ Homebrew-ready device
→ KPM（兼容时）/ validated legacy envelope（必要时）
→ Baga Ink Platform
→ IKP Package Manager
→ lifebook.ikp / other Baga Apps
→ Kindle Home Entry
```

关键边界：

- `.ikp` 永远不转换成 `.kpkg`；
- KPM 管 Native Platform Package，IKP Package Manager 管 Baga App；
- KPM missing != KPM incompatible；
- KOReader / koreader-base / FBInk 是内部 Implementation Source，不是 LifeBook API；
- Kindle Adapter 保持薄并复用成熟机制；
- Reader/UI、Jailbreak Route、KPM/MRPI、Home Entry、Build Tooling 不属于 Device Adapter Root Contract；
- 第一条真实 Bring-up 应先用代表性 `kindlehf` + Probe IKP，而不是直接开发完整 LifeBook。

仍未完成：

```text
platform/adapters/kindle/
KindleAdapterFactory
真实 Device Profiles / Quirk Sets
Base Display/Input/Storage/Lifecycle/Power Bindings
Pinned Product Integration
真机 Adapter Contract Tests
Base BICTS
baga-probe.ikp 真机运行
```

## 7. Licensing Architecture — CURRENT

Baga Ink 现在采用分层授权：

```text
Baga 自研 Platform / OEM 侧软件
→ 默认 PolyForm Noncommercial 1.0.0
→ OEM / 设备 / Platform 商业部署需要独立 Commercial License

普通 IKP App 开发
→ 保持低门槛；只使用公开 Baga API 开发并销售 App，本身不需要 OEM/Platform License

LifeBook 正式 App
→ Proprietary / Closed Source 第一方产品

第三方组件
→ 永远保持上游 License
```

License Cutover 不撤销历史 Apache-2.0 已经授予的权利。最后一个 Cutover 前 `main` commit 记录在 `LICENSE_HISTORY.md`。

Canonical Licensing Documents：

```text
LICENSE
docs/zh-CN/governance/02_Baga-Ink授权策略.md
COMMERCIAL_LICENSE.zh-CN.md
LICENSE_HISTORY.md
NOTICE
THIRD_PARTY_NOTICES.md
```

Repository Documentation Guard 现在也通过 `tools/check_licensing.py` 验证 Licensing Architecture。

为了保持未来 Community + Commercial Dual Licensing 能力，Dual-licensed Platform / Adapter 的外部代码贡献在 merge 前可能需要正式、经过法律审核的 CLA。

## 8. Compatibility Claim Boundary

目前没有正式声称某一个 Kindle、BOOX、iReader、Bigme、Hanvon 或其他 Android E-Paper 组合已经 `Baga Ink Compatible`。

正式 Compatibility Record 必须绑定精确 Device / Firmware / Platform / Adapter / Profile / Quirk / Contract / Lua Profile / BICTS Evidence。

Software License 本身也不自动授予 `Baga Ink Compatible` 官方品牌 / Certification 权利。
