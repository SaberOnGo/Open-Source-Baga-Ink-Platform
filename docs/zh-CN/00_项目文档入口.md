## 1. 第一次进入项目怎么读？

项目长期事实来源是 `main` 中的 Code、Tests、Machine-readable Spec 与 Approved Public Docs。Feature Branch、聊天记录、Draft PR 描述都不是长期项目知识库。

中文维护者推荐：

```text
README.zh-CN.md
   ↓
AGENTS.md                         （AI / 自动化贡献者）
   ↓
docs/zh-CN/00_项目文档入口.md
   ↓
docs/zh-CN/status/00_当前项目状态.md
   ↓
docs/zh-CN/standards/00_规范总览.md
   ↓
与任务相关的 Design / Reference App / Plan
   ↓
docs/zh-CN/governance/00_开发治理.md
```

## 4. 文件名规则

英文公共文档：

```text
NN_lowercase-kebab-case-name.md
```

简体中文公共文档：

```text
NN_中文名称.md
```

中文正文用中文把事情解释清楚，但 `Baga Ink`、`IKP`、`Device Adapter Contract`、`Capability`、`SQLite`、`Automerge`、`KOReader`、`FBInk` 等稳定技术身份不需要强行改名。

## 5. Machine Spec / Code 保持英文或语言无关

以下不按 Locale 复制：

```text
spec/
reference/
tests/
tools/
.github/
platform/
sdk/
client/
```

Public API、Schema Key、Error Code、CLI Flag、Source Identifier、Code Comment / Docstring、Test Name、Dependency Manifest、Commit Subject 使用英文。

## 6. 工程施工计划不强制全文翻译

`docs/plans/` 是工程工作区，不是 Public Protocol Authority，因此不要求把数千份 Task Design / AI Execution Prompt 全部复制成多语言。

特别是：

```text
docs/plans/platform-ports/kindle/
```

可以继续中文优先，并保持已建立的双语语义文件名、Task Version 与 Execution Prompt 规则。

但任何外部实现者需要长期依赖的稳定结论，MUST 提升回 Localized Standards / Design / Reference Apps / Governance / Status。
