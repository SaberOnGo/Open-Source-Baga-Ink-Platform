# Baga Ink 项目文档入口

> **文档级别：项目文档总入口**  
> **语言：简体中文（`zh-CN`）**  
> **状态：国际化基础 v0.1**  
> **日期：2026-08-23**

## 1. 长期事实来源

项目长期事实来源只有 `main` 分支中的代码、测试、机器规范和正式文档。Feature Branch、聊天记录、Draft PR 描述都不是长期项目知识库。

中文维护者推荐阅读顺序：

```text
AGENTS.md
   ↓
docs/README.zh-CN.md
   ↓
docs/zh-CN/00_项目文档入口.md
   ↓
docs/zh-CN/status/...
   ↓
docs/zh-CN/standards/...
   ↓
docs/zh-CN/governance/...
   ↓
与任务相关的 Design / Reference App / Plan
```

## 2. 公共文档按语言分目录

长期、公共、会被生态开发者依赖的正文文档采用：

```text
docs/en/
docs/zh-CN/
```

两种语言都镜像这些类别：

```text
standards/
design/
reference-apps/
governance/
status/
```

同一个编号代表同一个文档身份。例如最终目标：

```text
docs/en/standards/07_baga-ink-device-adapter-specification.md
docs/zh-CN/standards/07_设备适配器规范.md
```

这两份是 Standard 07 的不同语言版本，不是两套 Device Adapter Contract。

## 3. 文件名规则

英文公共文档：

```text
NN_lowercase-kebab-case-name.md
```

例如：

```text
00_baga-ink-standards-index.md
07_baga-ink-device-adapter-specification.md
11_baga-ink-kindle-adapter.md
```

简体中文公共文档：

```text
NN_中文名称.md
```

中文正文应当用中文解释清楚，但 `Baga Ink`、`IKP`、`Device Adapter Contract`、`Capability`、`SQLite`、`Automerge`、`KOReader`、`FBInk`、API 名称等具有稳定技术身份的术语不应该为了“全中文”而强行翻译。

## 4. 机器规范和代码保持英文/语言无关

以下目录不按语言复制：

```text
spec/
reference/
tests/
tools/
.github/
platform/     （未来产品源码）
sdk/          （未来 SDK 源码）
client/       （未来 Client 源码）
```

公开 API 名称、Schema Key、Error Code、CLI Flag、源码标识符、代码注释/Docstring、Commit Subject、机器可读 metadata 应使用英文。

## 5. 工程施工计划不强制双语复制

`docs/plans/` 是工程施工区，不是公开协议本身，因此不要求把几千份 Task Design / AI Execution Prompt 各复制一份英文。

特别是：

```text
docs/plans/platform-ports/kindle/
```

可以继续以中文为主，并保留当前“数字前缀 + 中文名 + 英文名”的可搜索文件名规则。这是维护者施工区。

但是，只要某个结论要成为国际开发者必须遵守的稳定事实，就必须回写到已经国际化的 Standards / Design / Reference Apps / Governance / Status，而不能只存在于中文 Task 或 AI Prompt。

## 6. 当前迁移状态

早期公共文档目前仍位于：

```text
docs/standards/
docs/design/
docs/reference-apps/
docs/governance/
docs/status/
```

这些目录现在定义为 **Legacy Migration Zone / 旧文档迁移区**。不再允许继续在这些目录新增公共文档。

每份旧文档的目标中文路径、目标英文路径和翻译状态由：

```text
docs/localization/catalog.json
```

统一登记。

迁移计划：

```text
docs/plans/02_文档国际化迁移计划_Documentation-Internationalization-Migration-Plan.md
```

在某份文档尚未进入 `current` 状态之前，可以明确标记 English translation pending；绝不能把未完成翻译的英文 Stub 当作正式英文 Standard。

## 7. 国际化规则

中文版本：

```text
docs/zh-CN/governance/01_文档国际化与本地化规范.md
```

英文版本：

```text
docs/en/governance/01_documentation-internationalization-policy.md
```

它们共同定义语言地位、同步规则、技术术语、命名规则、迁移流程和 CI Gate。
