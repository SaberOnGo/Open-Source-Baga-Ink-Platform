## 1. 第一次进入项目怎么读？

项目长期事实来源是 `main` 分支中的代码、Tests、Machine-readable Spec 与 Approved Public Docs。Feature Branch、聊天记录、Draft PR 描述都不是长期项目知识库。

中文维护者推荐阅读顺序：

```text
README.zh-CN.md
   ↓
AGENTS.md                         （AI / 自动化贡献者）
   ↓
docs/zh-CN/00_项目文档入口.md
   ↓
docs/zh-CN/status/00_当前项目状态.md
   ↓
与任务相关的 Standards
   ↓
与任务相关的 Design / Reference App / Plan
   ↓
docs/zh-CN/governance/00_开发治理.md
```

当前正式 Governance：

```text
docs/zh-CN/governance/00_开发治理.md
docs/zh-CN/governance/01_文档国际化与本地化规范.md
```

## 2. 公共文档按语言分目录

长期、公共、会被生态开发者依赖的正文采用：

```text
docs/en/
docs/zh-CN/
```

两种语言镜像这些类别：

```text
standards/
design/
reference-apps/
governance/
status/
```

同一个编号代表同一个 Document Identity。例如：

```text
docs/en/standards/07_baga-ink-device-adapter-specification.md
docs/zh-CN/standards/07_设备适配器规范.md
```

它们都是 Standard 07 的语言版本，不是两套 Device Adapter Contract。

## 4. 文件名规则

英文公共文档：

```text
NN_lowercase-kebab-case-name.md
```

例如：

```text
00_baga-ink-standards-index.md
07_baga-ink-device-adapter-specification.md
11_baga-ink-kindle-adapter.md
```

简体中文公共文档：

```text
NN_中文名称.md
```

中文正文应该用中文把事情解释清楚，但 `Baga Ink`、`IKP`、`Device Adapter Contract`、`Capability`、`SQLite`、`Automerge`、`KOReader`、`FBInk` 等稳定技术身份不需要为了“全中文”强行改名。

## 5. Machine Spec 和代码保持英文 / 语言无关

以下目录不按 Locale 复制：

```text
spec/
reference/
tests/
tools/
.github/
platform/     （未来 / Reference Platform 源码）
sdk/          （未来 Generated / Platform SDK）
client/       （未来 Baga Ink Client）
```

Public API、Schema Key、Error Code、CLI Flag、源码 Identifier、Code Comment / Docstring、Test Name、Dependency Manifest、Commit Subject 使用英文。

---

## 6. 工程施工计划不强制全量翻译

`docs/plans/` 是工程施工区，不是 Public Protocol Authority，因此不要求把几千份 Task Design / AI Execution Prompt 全部复制成多语言。

特别是：

```text
docs/plans/platform-ports/kindle/
```

可以继续中文优先，并保持已经建立的双语语义文件名、Task Version 与 Execution Prompt 规则。

但只要某个结论成为外部开发者必须依赖的稳定事实，就必须提升回 Localized Standards / Design / Reference Apps / Governance / Status，不能永远只存在于中文 Task 或 Prompt。
