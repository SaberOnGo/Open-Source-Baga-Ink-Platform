# 文档国际化与本地化规范

> **文档级别：项目治理规范**  
> **Document ID：`governance.localization.01`**  
> **语言：简体中文（`zh-CN`）**  
> **状态：Governance Baseline v1.0**  
> **日期：2026-08-23**  
> **对应英文版：`docs/en/governance/01_documentation-internationalization-policy.md`**

## 0. 目的

Baga Ink 面向不同国家、不同语言的开发者长期协作，因此公共长期文档按 Locale Tree 维护，而不是把多种语言塞进同一个文件名或同一段正文。

目标：

- 中文维护者可以直接阅读、编写完整中文技术说明；
- 国际开发者可以从完整英文文档理解同一个项目；
- 不同语言不能逐渐漂移成两套 Protocol / Architecture；
- Machine-readable Contract、Code、Tests、Identifier、Tooling 保持共享并使用英文/语言无关形式；
- 海量工程 Task / AI Execution Prompt 不需要浪费成本全部做多语言镜像。

## 1. 永久 Locale Architecture

公共、长期正文只允许存在于：

```text
docs/en/
docs/zh-CN/
```

受治理的 Public Category：

```text
standards/
design/
reference-apps/
governance/
status/
```

早期中英混合 Public Directories 已废止，MUST NOT 重新出现。

## 2. 同一个 Document Identity，不按语言分叉协议

中英文对应文档是**同一个逻辑文档的不同语言版本**。

任何一个 Locale Edition 都不得静默引入另一套：

```text
Architecture
Requirement
API Contract
Permission Rule
Compatibility Rule
Signing / Identity Rule
Distribution / Update Rule
Implementation Freeze
```

权威顺序：

```text
Machine-readable Spec / Schema / Test Vector / Executable Conformance Evidence
        ↓ 在覆盖范围内优先
Approved Project Semantic Decision + Stable Document Identity
        ↓
Maintained Locale Editions
```

如果某个纯文字语义中英文发生冲突，这是 Documentation Defect，必须先解决，相关要求才能进入 Stable Baseline。

## 3. Stable Document Identity

`docs/localization/catalog.json` 记录每份 Public Doc 的：

```text
id
category
number
en_path
zh_cn_path
status
legacy_path = null
```

同一 Category 内数字前缀是稳定 Document Number。

例如：

```text
docs/en/standards/07_baga-ink-device-adapter-specification.md
docs/zh-CN/standards/07_设备适配器规范.md
```

两份都代表 Standard 07。

## 4. 文件名规则

### English Public Docs

```text
NN_lowercase-kebab-case-name.md
```

要求：

- 两位稳定编号；
- ASCII lowercase kebab-case 描述名；
- 不包含中文字符；
- 不再使用“中文 + 英文”双语文件名。

### 简体中文 Public Docs

```text
NN_中文名称.md
```

要求：

- 与英文 Counterpart 使用同一个稳定编号；
- 描述名以中文为主；
- 稳定技术身份可以保留英文；
- 不再追加冗余英文后缀，因为 Locale Directory 已经标明受众语言。

根目录的 `README.md`、`README.zh-CN.md`、`CONTRIBUTING.md`、`CONTRIBUTING.zh-CN.md`、`AGENTS.md` 属于单独治理的入口文件例外。

## 5. 正文语言与技术术语

英文 Public Docs SHOULD 使用英文解释。

简体中文 Public Docs SHOULD 用中文把事情解释清楚，但稳定技术身份继续保持可识别，例如：

```text
Baga Ink Platform
Baga Ink API
Baga Device Adapter Contract
IKP
Capability
Permission
SQLite
Automerge
KOReader
FBInk
KPM
MRPI
BICTS
```

不要为了“全中文”机械翻译 Identifier，造成第二套技术词汇或不兼容 API 名称。

Canonical Terminology 由：

```text
docs/localization/terminology.json
```

机器记录。

## 6. Machine / Code Surface 保持英文或语言无关

以下目录不按 Locale 复制：

```text
spec/
reference/
tests/
tools/
.github/
platform/
sdk/
client/
```

以下 SHOULD 使用英文：

- Localized prose tree 之外的源码文件/目录名；
- Code Identifier、Comment、Docstring；
- Public API / Module Name；
- JSON/YAML/TOML Key 与 Schema ID；
- Machine Error Code；
- CLI Command / Flag；
- Test Name；
- Dependency Manifest；
- Commit Subject / Release Tag。

## 7. Operational Engineering Plans 不强制全文本地化

`docs/plans/` 是工程施工区，不是 Normative Public Protocol Surface。

不要求把每份 Task Design / AI Execution Prompt 复制成多个 Locale。

特别是：

```text
docs/plans/platform-ports/kindle/
```

可以继续中文优先，并保持严格可搜索的双语文件名规则。

但是：

> **只要某个稳定结论成为外部实现者必须依赖的事实，就 MUST 提升回 Localized Standards / Design / Reference Apps / Governance / Status，不能永远只存在于中文 Task 或 Prompt。**

## 8. Maintained Pair 同步规则

对于 Catalog 中 `status = current` 的文档，语义修改 SHOULD 在同一个 Reviewed PR 中同步修改所有维护中的 Locale Counterpart。

如果确实不能立即同步，Catalog 必须显式标记 pending/stale；Stable Release Process 不能把它视为已同步。

`superseded` 用于明确不再作为当前权威的历史兼容入口。

## 9. Repository 首页语言模型

国际项目默认入口：

```text
README.md              → English default
README.zh-CN.md        → 简体中文
CONTRIBUTING.md        → English default
CONTRIBUTING.zh-CN.md  → 简体中文
AGENTS.md              → English AI / Automation Instructions
```

README Locale Registry：

```text
docs/localization/readme-languages.json
```

所有 Current README Locale 都必须展示同一组受治理的语言切换入口。

## 10. 未来新增 Locale

未来增加 `ja`、`de`、`fr`、`ko` 等 Locale，必须先做明确 Governance 修改。

一个 Maintained Locale 至少应有：

- 合法 BCP 47-style Locale Tag；
- Root README Translation 时的 Registry Entry；
- `docs/<locale>/` 文档树；
- Maintainer / Review Ownership；
- 必要的 Glossary / Terminology Policy；
- Catalog 中明确的同步状态；
- CI Validation。

禁止创建：

```text
chinese/
english/
cn/
zh/
docs/standards/en/
```

这类平行结构。

## 11. AI / Contributor Hard Gate

创建、重命名、移动、翻译、修改 Public Long-lived Documentation 前，Contributor / AI MUST 遵守本规范。

优先使用：

```text
python3 tools/new_localized_doc.py ...
```

完成前必须通过：

```text
python3 tools/check_docs_i18n.py
```

CI 至少拒绝：

- 重新创建旧中英混合 Public Directories；
- 非法 Locale Path；
- 非法英文/中文文件名；
- 未登记到 Catalog 的 Public Doc；
- 重复 Document ID / Target Path；
- 迁移完成后出现非 null `legacy_path`；
- `current` / `superseded` 缺失 Maintained Counterpart；
- 未经 Governance 引入的嵌套 Category Structure。

AI MUST NOT 为了让错误结构通过而削弱 Guard、扩大 Allowlist 或随意修改 Catalog。

## 12. 最终规则

> **Public Project Knowledge 按 Locale Tree 本地化；Protocol 与 Implementation Contract 始终只有一个项目；Operational Engineering Plans 可以保留 Maintainer Language；Machine Surface 保持共享并使用英文/语言无关形式。任何语言版本都不能成为 Baga Ink 的隐藏 Fork。**
