## 0. 目的 / Purpose

Baga Ink Permission Model 定义第三方 IKP App 可以访问哪些用户数据、设备能力和平台资源。

核心目标：

> **Capability 决定设备“能不能”，Permission 决定 App“可不可以”。**

Baga Ink MUST 避免两种极端：

1. 像传统脚本一样默认拥有设备全部权限；
2. 为每个小动作弹窗，破坏墨水屏的低干扰体验。

因此采用：

```text
Manifest 预声明
+ 最小权限
+ 高风险能力按需确认
+ 可撤销授权
+ 无系统权限 UI 的设备由 Platform 自己提供统一授权界面
```

---

# 1. 基本原则

1. App MUST 在 IKP Manifest 中预声明可能使用的权限；
2. App MUST 不申请 Manifest 未声明的权限；
3. Platform MUST 默认拒绝未授权资源；
4. Permission 与 Capability MUST 分离；
5. Platform MAY 根据设备限制采用不同底层授权实现，但对 App 语义一致；
6. 用户撤销权限后，App MUST 正确处理 `permission_denied`；
7. Universal App MUST 不通过 Shell / Vendor API / Native escape 绕过权限系统。

---

# 2. 权限状态

每个权限至少有：

```text
not_declared
not_granted
granted
denied
restricted
```

含义：

- `not_declared`：Manifest 未声明，运行时不可申请；
- `not_granted`：已声明但尚未授权；
- `granted`：允许；
- `denied`：用户或策略拒绝；
- `restricted`：设备 / 管理策略 / Platform 不允许授予。

Platform MAY 保存：

```text
grant_once
grant_while_using
grant_persistent
```

但 v0.1 不要求所有设备都支持三种模式。

---

# 3. API 关系

标准接口：

```lua
baga.permissions.check(name)
baga.permissions.request(name)
baga.permissions.list()
```

`request()` MAY 是异步 Task。

例如：

```lua
if not baga.permissions.check("network") then
    baga.permissions.request("network")
end
```

Platform MUST 不因为 App 调用了 API 就自动授予权限。

# 4. v0.1 权限注册表

## 4.1 `network`

允许 App 通过 Baga Ink Network API 发起网络请求。

不允许：

- raw socket 绕过 Platform；
- 私自修改系统 Wi-Fi 配置；
- 通过 Shell 执行网络命令。

## 4.2 `library.read`

允许读取用户书库中 Platform 暴露的书籍元数据及授权内容。

不表示可以遍历整个文件系统。

## 4.3 `library.write`

允许对用户书库执行标准化写操作，例如导入、删除、移动等。

由于存在用户数据损失风险，Platform SHOULD 对危险写操作增加确认或回收站机制。

## 4.4 `notes.read`

允许读取 Baga Ink 标准笔记 / 标注资源。

## 4.5 `notes.write`

允许新增、修改标准笔记 / 标注。

## 4.6 `user_files.read`

允许读取用户显式选择或授权的普通文件。

MUST 不等价于整个磁盘读取权限。

## 4.7 `user_files.write`

允许向用户显式选择或授权的位置写文件。

## 4.8 `clipboard`

允许读取或写入统一剪贴板能力。

如底层设备没有系统剪贴板，Platform MAY 实现自己的轻量剪贴板。

## 4.9 `audio.output`

允许 App 使用音频输出。

Capability 不存在时即使授权也返回 `not_supported`。

## 4.10 `bluetooth`

允许使用 Baga Ink 暴露的蓝牙能力。

扫描、连接等高频或高隐私操作 MAY 进一步拆分权限。

## 4.11 `frontlight.control`

允许修改设备前光。

读取当前前光值 MAY 不要求同等级权限；写入需要控制权限。

## 4.12 `power.keep_awake`

允许 App 请求短时间保持唤醒。

Platform 始终保留拒绝不合理请求的权利。

# 5. 权限分级

为了减少不必要弹窗，权限 SHOULD 分为：

```text
Level 0: Sandbox internal
Level 1: Low-risk shared capability
Level 2: User data access
Level 3: Device control / privacy-sensitive
```

## Level 0

例如：

```text
appdata
cache
```

App 不需要用户确认，因为只影响自身沙箱。

## Level 1

例如普通网络访问，可由用户全局策略控制。

## Level 2

例如：

```text
library.read
notes.read
user_files.read
```

涉及用户数据，应透明展示。

## Level 3

例如：

```text
library.write
user_files.write
bluetooth
frontlight.control
power.keep_awake
```

Platform SHOULD 更谨慎授权。

---

# 6. Manifest 预声明

示例：

```json
{
  "permissions": [
    "network",
    "library.read",
    "notes.write"
  ]
}
```

Market MUST 能在安装前展示权限摘要。

如果新版本新增权限：

```text
v1.2: network
v1.3: network + user_files.write
```

Platform / Market SHOULD 将其视为重要更新，并向用户明确提示。

---

# 7. Kindle 与 Android 的一致语义

底层权限机制可以不同。

Android：

```text
Android permission / SAF / app sandbox / vendor policy
```

Kindle：

```text
Baga Ink Platform 自己的 permission policy + filesystem isolation + bridge rules
```

但 App 看到的始终是：

```lua
baga.permissions.check(...)
```

不能让 App 因为 Kindle 没有 Android permission dialog 就自动得到更高权限。

---

# 8. 用户授权 UI

授权界面 SHOULD：

- 高对比度；
- 文字简短；
- 不依赖动画；
- 清楚说明“为什么需要”；
- 清楚说明访问范围；
- 允许拒绝；
- 允许以后在 Settings 修改。

不建议：

```text
允许访问所有文件？
```

优先：

```text
允许 Example Reader 读取你选择的书籍？
```

权限语言必须与实际技术范围一致。

---

# 9. 数据域隔离

Baga Ink SHOULD 把数据分成：

```text
App Private Data
User Library
Notes / Highlights
User-selected Files
Shared Platform Data
System / Device Data
```

App Private Data 默认仅 App 自己可访问。

跨 App 数据共享 MUST 通过明确平台 API，而不是共享真实目录。

---

# 10. 撤销权限

用户撤销后：

- Platform MUST 立即或在安全边界内生效；
- App SHOULD 收到标准权限变化事件；
- 已缓存的敏感数据处理规则由后续 Data Policy 定义；
- App MUST 不反复骚扰式请求已被拒绝的权限。

Platform MAY 对连续请求进行节流。

---

# 11. 后台行为

Baga Ink 是低功耗墨水屏平台，后台能力默认收紧。

拥有 `network` 不等于 App 可以无限后台联网。

拥有 `power.keep_awake` 不等于 App 可以永久禁止休眠。

平台政策始终可以根据：

```text
battery
charging state
Wi-Fi state
sleep policy
user settings
```

限制执行。

---

# 12. 高风险能力不进入通用权限

以下能力 v0.1 不作为普通 Universal App Permission：

```text
raw shell
process spawn
kernel access
raw framebuffer
Android Context
direct JNI
Vendor SDK
system package install
arbitrary filesystem root
```

这些属于 Platform Core / Device Adapter / 受控 Extension 的实现层。

---

# 13. Permission 与 Market

Baga Ink Market SHOULD 展示：

```text
权限名称
用途说明
首次引入版本
风险级别
```

Market MAY 对高风险权限进行额外审核。

Universal 标识不代表“零权限”，而代表权限都通过标准机制透明声明并受控执行。

---

# 14. Permission 测试

Compatibility Test Suite MUST 验证：

- 未声明权限不可获得；
- denied 状态正确返回；
- sandbox 不可越界；
- permission revoke 后 App 无法继续访问；
- Kindle 与 Android 返回相同错误语义；
- App 无法通过标准 Lua 环境绕过限制。

---

# 15. 核心原则 / Core Rule

> **Capability 解决碎片化，Permission 解决边界。二者必须分开。**

一个稳定的权限模型让 Baga Ink 可以保持开放开发，同时避免“Lua App = 任意系统脚本”这种失控局面。
