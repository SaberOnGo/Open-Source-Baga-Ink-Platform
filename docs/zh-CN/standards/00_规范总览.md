## 2. Platform 核心闭环

```text
App Standard
   ↓
Baga Ink API + Baga Lua Profile / Standard Libraries
   ↓
Baga Ink Platform Core
   ↓
Device Adapter Contract
   ↓
Kindle / Android E-Paper / future OEM devices
   ↓
Adapter Contract Tests + Compatibility Standard + BICTS
```

关键区分：

```text
baga.*
→ 统一 Device / OS / Platform 差异

Device Adapter Contract
→ 规定新设备接入 Baga 必须实现什么

Standard Libraries / Adopted Components
→ 直接采用成熟通用软件能力
```

当前重要例子：

```text
SQLite + lsqlite3
→ Stable Standard Library

Automerge core
→ Adopted Local-first / CRDT Foundation
→ 可以整体采用，也可以拆模块采用

KOReader / FBInk / Vendor SDK / OS mechanisms
→ Device / Platform 内部成熟实现来源
→ 不因为被复用就自动成为新的 Baga 公共架构层
```

如果 App 绕过这个闭环直接依赖私有设备 API，Baga 会重新碎片化；如果把成熟通用库无意义地再包装一层，也会产生重复且更弱的抽象。

## 3. Device Adapter 的正式定位

Standard 07 面向：

```text
Baga Platform implementer
OEM / device vendor
第三方设备移植者
Adapter maintainer
```

它定义：

```text
Root Adapter / Factory
DeviceDescriptor
Capability Snapshot
Display / Input / Storage / Lifecycle / Power typed subsystems
Optional Network / Light / Audio / Bluetooth / UserLibrary
Event / Error model
Device Profile / Quirk Set
Self-test
Contract Versioning
Adapter Contract Tests
```

核心原则：

> **Contract 定义“必须提供什么”，不要求重新实现设备已有能力。**

Kindle Adapter SHOULD 最大化复用 KOReader、FBInk、Kindle OS / Homebrew 已验证能力，只补 Baga Contract 所需的薄映射、归一化、Profile / Quirk 与测试。

## 4. Distribution Security 闭环

```text
Publisher Identity
        ↓
App Ownership + App Key Delegation
        ↓
Publisher-signed IKP
        ↓
Signed Repository Metadata
        ↓
Baga Ink Client / Device Direct / Offline Snapshot
        ↓
Device Final Verification
        ↓
Staged Install → Health Check → Active / Rollback
```

Publisher Signature、Repository Metadata、Local Installed Identity 是不同信任层，不能互相替代。

## 10. Authority Boundaries

```text
01      顶层战略 / 公共架构
02      合规 Baga Ink App
03      公开 baga.* API
04      Capability
05      Permission
06      IKP
07      Device Adapter Porting Contract
08 / 10 Compatible / Tests
11 / 12 Device Family 对 Standard 07 的实现映射
13      Standard Libraries / Adopted Mature Components
20–28   Distribution / Security / Update / Catalog
```

新增平台抽象前必须先看 Standard 13：成熟通用库已经提供更好抽象时，应优先直接采用，不再造更弱的私有包装。

Device Adapter 同样遵守：优先复用 OS / Vendor SDK / Homebrew / Mature Open-source Capability，再补 Contract 所需薄映射。

## 11. Change Governance

- 修改 01–03 需要 Architecture-level Review；
- Standard Library / Adopted Component 决策更新 13；
- 新 Capability 更新 04；
- 新 Permission 更新 05；
- IKP 变化更新 06；
- Device Adapter Contract 变化更新 07；
- Kindle / Android family mapping 更新 11 / 12；
- Adapter Machine IDL / Codegen 必须和 07 同步并跑 Compatibility Check；
- Compatible 行为变化更新 08 / 10；
- SQLite / lsqlite3 Baseline 变化必须跑 BICTS Regression；
- Automerge 如果升级成 Stable Developer-facing Lua Module / Wire Protocol，必须明确版本和 Migration，不允许只写“latest”；
- 已替换/否决的接口、namespace、架构草案必须退出 Current Standards / Reference Apps，历史由 Git 保存。

## 13. 核心判断

Baga Ink 的统一来自：

```text
设备差异 → Device Adapter Contract → 稳定 Baga API
成熟通用软件 → 直接采用优秀 Standard Library / Foundation
安装 / 更新 / Permission / Compatibility → 统一协议与测试
```
