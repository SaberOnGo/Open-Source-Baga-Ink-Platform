# v1.1 K7：Baga Ink Client 与 Route DB 自动化计划

**目标**: 只有设备端 Platform 已稳定以后，才把 Kindle enablement/bootstrap/install/IKP transfer 自动化到 Baga Ink Client。

---

## 1. Client 两个独立职责

```text
A. Ensure Baga Ink Platform
B. Transfer / Install IKP
```

两者不能混成一个不可诊断事务。

---

## 2. Scope

```text
K7-1  USB/transport Kindle detection
K7-2  exact model / firmware / current-state collection
K7-3  Installation Route DB schema
K7-4  exact route matching/ranking
K7-5  Homebrew foundation state detection
K7-6  distinguish KPM-compatible vs KPM-installed
K7-7  verified KPM bootstrap
K7-8  verified fallback envelope when KPM unavailable/unvalidated
K7-9  Platform ensure/install/health result
K7-10 filesystem mailbox or controlled handshake
K7-11 signed IKP transfer
K7-12 device-side re-verification/install/result outbox
K7-13 recovery/data-protection UX
K7-14 route regression matrix
```

---

## 3. Route DB Boundary

可以记录：

```text
WinterBreak
SpringBreak
Sanctuary
Véra
legacy verified routes
future verified routes
```

每条 route 必须绑定适用的精确设备/固件/状态证据。

这些 route 不进入：

```text
Platform Core
Device Adapter Contract
IKP App contract
```

---

## 4. Conservative Resolver

未知组合默认：

```text
Experimental / Unsupported / Needs verification
```

不能因为相似型号或相近 firmware 自动继承可执行 jailbreak/install route。

---

## 5. RED Tests

```text
unknown firmware incorrectly matched to stable route
KPM missing incorrectly treated as incompatible
wrong Platform native target selected
IKP transferred without device-side re-verification
failure path deletes Kindle books/notes/App data
stale result mailbox accepted as current result
```

---

## 6. K7 Gate

对至少一条精确验证设备组合完成：

```text
Detect
→ collect state
→ choose exact route when needed
→ reach/confirm Homebrew-ready
→ ensure correct KPM/installer path
→ install/verify Platform
→ transfer/install IKP
→ verify final launch/result
```

整个流程必须有可恢复错误状态和可诊断证据。
