# v1.1 K6：KPM 与 Kindle Home 入口计划

**目标**: 当 Platform/Probe/Reader 设备侧链稳定后，把开发部署收敛为正常 Kindle native Platform installation 和 Kindle Home 产品入口。

---

## 1. 固定关系

```text
KPM `.kpkg`
→ Baga Ink Platform native package

IKP
→ Baga App package
```

不存在：

```text
lifebook.ikp → lifebook.kpkg
```

---

## 2. Scope

```text
K6-1  build baga-platform_<version>_kindlehf.kpkg
K6-2  install / launch / uninstall hooks
K6-3  pinned component manifest inside release
K6-4  post-install/update health check
K6-5  sh_integration Home Entry
K6-6  Kindle Home → LifeBook/Probe → baga-launch <app-id>
K6-7  update preserves books/notes/App data
K6-8  uninstall follows user-data policy
K6-9  MRPI/legacy envelope only where KPM unavailable/unvalidated
K6-10 deeper AppMgr registration as later optional enhancement
```

---

## 3. User/Product Path

外部可见路径：

```text
Kindle Home
→ LifeBook
```

内部：

```text
Home Entry
→ baga-launch com.lifebook
→ Platform Core
→ active lifebook.ikp
```

正常使用路径不要求打开 KOReader FileManager、KUAL、KPM CLI 或 MRPI。

---

## 4. KPM State

必须区分：

```text
KPM compatible but not installed
→ bootstrap/install KPM first

KPM unavailable or unvalidated for exact combination
→ verified MRPI/legacy/manual envelope
```

不能把“没安装”误判为“不兼容”。

---

## 5. RED Tests

```text
wrong native-target package rejected
interrupted install leaves recoverable previous Platform
health check failure prevents promotion
update deletes App data -> test failure
Home Entry launches bypassing baga-launch -> test failure
```

---

## 6. K6 Gate

```text
[ ] .kpkg installs exact target Platform
[ ] health check succeeds
[ ] update preserves user/App data according to policy
[ ] uninstall behavior verified
[ ] Kindle Home launches Baga app through Platform
[ ] ordinary user path does not expose underlying Homebrew tools
```
