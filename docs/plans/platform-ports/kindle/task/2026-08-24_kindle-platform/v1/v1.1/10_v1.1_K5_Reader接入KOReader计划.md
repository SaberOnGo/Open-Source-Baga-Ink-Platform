# v1.1 K5：Reader 接入 KOReader 计划

**目标**: Probe 链稳定以后，通过 Baga `baga.reader` API 使用 Kindle Platform 内部的 KOReader reader stack，不重写 EPUB/PDF reader。

```text
IKP
→ baga.reader
→ Platform Reader implementation
→ ReaderUI / CREngine / MuPDF
→ Kindle Device Adapter
```

---

## 1. Dependency Gate

K3 Platform/Probe 链稳定；K4 App release/lifecycle 基础足以进行受控 Reader 测试。

---

## 2. Scope

```text
minimal internal Reader bridge
opaque source handle → reader open
EPUB/TXT bring-up via CREngine
PDF bring-up via MuPDF
page/position mapping
search mapping
selection mapping
bookmark/highlight/annotation mapping where Baga API requires
suspend/resume
position persistence
reader regression / BICTS subset
```

---

## 3. 固定边界

LifeBook/IKP 不允许：

```lua
require("ui/uimanager")
require("apps/reader/readerui")
```

KOReader private object/module/path 只存在于 Platform implementation 内。

ReaderUI/CREngine/MuPDF 不属于 Device Adapter root subsystem。

---

## 4. 实现策略

```text
public baga.reader semantic operation
→ internal bridge
→ KOReader reader operation
→ result normalized back to Baga semantic model
```

优先复用 KOReader 已有 position/search/selection/highlight 能力；只有公共 Baga API 要求而 KOReader 当前 substrate 缺失的部分才增加 Platform glue。

---

## 5. RED/GREEN Gate

RED 至少覆盖：

```text
IKP direct KOReader private import rejected
unsupported source handle rejected
position lost across reopen
sleep/wake breaks active document
```

GREEN 至少证明：

```text
[ ] EPUB/TXT open via Baga API
[ ] PDF open via Baga API
[ ] page/position/search round-trip
[ ] selection mapping works for supported content
[ ] position survives suspend/resume
[ ] App never receives KOReader private object
```

---

## 6. Out of Scope

K5 不重新实现 KOReader reader engine，也不负责 KPM packaging、Home Entry 或 Client automation。
