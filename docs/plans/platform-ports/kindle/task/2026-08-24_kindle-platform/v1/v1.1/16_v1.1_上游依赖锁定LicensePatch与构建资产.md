# v1.1 上游依赖锁定、License、Patch 与构建资产

**职责**: 规定首台 stock 设备准备与 Kindle Platform 采用的上游组件怎样锁定、怎样记录本地 patch、怎样关联构建与真机证据。

---

## 1. Batch 0：Jailbreak route 上游证据

首台 5.16.3 stock 开发机在执行 WinterBreak2 前，必须记录当前上游证据，不把 exploit payload 复制进 Baga 仓库。

至少记录：

```text
KindleModding Jailbreaking Wizard confirmation result（不记录 serial）
WinterBreak2 upstream repository / current release
WinterBreak2 guide last checked date
OTA-prevention guide last checked date
What's Next / KPM guide last checked date
fallback guidance last checked date
```

本任务包当前依据：

```text
https://kindlemodding.org/kindle-models
https://kindlemodding.org/jailbreaking/WinterBreak2/
https://kindlemodding.org/jailbreaking/prevent-auto-update/
https://kindlemodding.org/jailbreaking/whats-next/
https://kindlemodding.org/kindle-dev/kindle-sdk.html
```

WinterBreak2 等 jailbreak 是设备准备/未来 Client Route DB 的 upstream route，不是 Baga Platform 或 Device Adapter dependency。

## 3. KOReader / koreader-base Pin

Baga Kindle Platform 第一阶段使用自己锁定、验证的 component set，不依赖用户自行安装的 KOReader。

每次升级必须比较：

```text
bootstrap entry
Kindle Device implementation
screen/input APIs
lifecycle behavior
Reader/UI private APIs used by Platform
local Baga patch applicability
kindlehf build output
Contract/BICTS evidence
```

不能只改 commit SHA 后直接宣称兼容。

首台设备 firmware 5.16.3；Kindle SDK 当前将 firmware `>=5.16.3` 映射为 `kindlehf`。该映射属于 K1 build input，但仍须真实 artifact/device evidence。

---

## 4. Local Patch Policy

每个 Baga-specific patch 必须记录：

```text
patch id/name
upstream base commit
files/symbols touched
purpose
why wrapper/config alone is insufficient
expected upstream-upgrade conflict surface
tests covering patch
```

K1 direct-entry patch SHOULD 极小，只增加受控 private entry，而不重构 KOReader 主启动链。

---

## 5. FBInk

FBInk 保持其上游 native/C 实现和许可证。Baga 只在需要的 Kindle profile/backend 中通过现有或窄 binding 使用。

不得：

```text
为了统一语言复制/改写 FBInk implementation
把 FBInk API 暴露给 IKP
把 FBInk license 替换成 Baga license
```

---

## 6. Build Assets

至少保存/可重建：

```text
toolchain version
native target
build command
upstream pins
local patches
configuration flags
output file names
artifact hashes
```

K1 Gate 的关键不是“某台机器上曾经编译成功”，而是 pinned inputs 能重复得到可验证的 `kindlehf` artifact。

---

## 7. KPM / Homebrew Assets

需要区分两件事：

```text
Batch 0 modern jailbreak result
→ 首台开发机应已经拥有 KPM/Homebrew foundation

K6
→ Baga Platform 正式 `.kpkg` packaging / install / update / uninstall
```

因此首台设备的 KPM 版本/状态可在开发 evidence 中记录；真正进入 K6 时再锁定 Baga product packaging 所依赖的：

```text
KPM version/commit
package manifest format assumptions
install/launch/uninstall hooks
sh_integration assets
MRPI/legacy fallback envelope source/compatibility evidence
```

KPM 等 install components 不应误写进 Device Adapter dependency manifest；它们属于 Platform native build/install manifest。

---

## 8. License Gate

任何 bundling/modification/linking/invocation 方式改变时重新检查：

```text
LICENSE
NOTICE
THIRD_PARTY_NOTICES.md
docs/zh-CN/governance/02_Baga-Ink授权策略.md
```

第三方组件始终保留其上游许可义务。

Jailbreak route upstream 通常不随 Baga Platform 分发；若未来 Baga Ink Client 需要下载、缓存或重新分发相关 payload，K7 必须单独检查其 license/distribution 条件。
