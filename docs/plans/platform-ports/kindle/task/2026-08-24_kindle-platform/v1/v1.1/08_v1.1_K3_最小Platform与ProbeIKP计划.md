# v1.1 K3：最小 Platform 与 Probe IKP 计划

**目标**: 第一次在真实 Kindle 上运行真正的 Baga `.ikp`，验证 UI、Input、Storage、Lifecycle、Power 的最小闭环。

---

## 1. Dependency Gate

前置：K0、K1、K2 Gate 全部通过。

---

## 2. Minimal Platform Core v0.0.1

只实现 Probe 所需职责：

```text
App Registry
App Context
Embedded Lua Host
Lifecycle dispatch
Adapter dispatch
Permission/Sandbox skeleton
baga.app
baga.device
baga.storage
baga.log
minimal baga.ui
developer-mode local IKP loading
```

暂不实现：

```text
AI
Sync
Market
Bluetooth
Audio
Pen
full Reader
production IKP update pipeline
```

---

## 3. `baga-probe.ikp`

Probe 至少显示：

```text
Platform version
Adapter version
model / firmware / native target
Base capabilities
Display status
Input status
Storage status
Lifecycle status
Power status
Counter
[ +1 ]
```

验证链：

```text
Counter 1
→ +1
→ Counter 2
→ sleep
→ wake
→ Counter still 2
```

---

## 4. Developer-mode IKP

K3 允许开发模式本地包，只先完成：

```text
manifest parsing
entry resolution
controlled app root
load main.lua
launch lifecycle
```

生产级 signature/staging/activation 属于 K4。

---

## 5. RED Tests

实现前建立失败测试：

```text
unknown/missing app manifest rejected
App cannot access another app storage root
lifecycle does not reach app before dispatcher exists
counter is not persistent before storage integration
sleep/wake state is lost before lifecycle integration
IKP tries to import KOReader private module and is rejected by boundary tests
```

---

## 6. K3 Gate

真实设备必须通过：

```text
real Kindle
→ baga-launch
→ Platform Core
→ Kindle Adapter
→ baga-probe.ikp
→ visible UI
→ normalized input
→ persistent state
→ sleep/wake
→ state remains valid
```

需要保存 build digest、device facts、launch log、Probe screen evidence、storage result 与 sleep/wake result。

---

## 7. Write Scope

允许主要修改：

```text
platform/core/**
platform/lua/**
apps/probe/**
tests/platform/**
tests/kindle/probe/**
```

K3 不实现 Reader、KPM 产品包或 Client automation。
