# v1.1 总控：Kindle Platform 首轮实现范围、边界与执行纪律

**日期**: 2026-08-24  
**任务定位**: 本目录是 Baga Ink Platform Kindle Reference Port 的第一份完整实现任务包。  
**当前工程焦点**: K0 + K1；K2–K7 在同一目录中保留完整后续路线。  
**首个真实设备**: Homebrew-ready `kindlehf`，firmware >= 5.16.3。  
**执行方式**: 未指定 Batch 时从 Batch 0 开始；当前 Batch Gate 全部通过后才能进入下一 Batch。

---

## 1. 本轮最终目标

本任务包覆盖从可执行 Device Adapter Contract 到 Kindle Client 自动安装的完整 K0–K7 路线，但首轮真正进入代码实施的是 K0 与 K1。

第一条重大真机验收链：

```text
real Homebrew-ready Kindle
        ↓
baga-launch
        ↓
pinned KOReader/koreader-base substrate
        ↓
Baga Ink Platform Core
        ↓
Kindle Device Adapter
        ↓
baga-probe.ikp
        ↓
visible UI + normalized input
        ↓
persist state
        ↓
sleep / wake
        ↓
state remains valid
```

`baga-probe.ikp` 是第一份真实 IKP。完整 LifeBook 不替代基础 Probe Gate。

## 4. 固定架构边界

必须服从：

```text
docs/zh-CN/standards/07_设备适配器规范.md
docs/zh-CN/standards/11_Kindle适配规范.md
docs/zh-CN/design/02_设备适配器可执行契约与SDK设计.md
docs/zh-CN/reference-apps/03_Kindle具体实现架构冻结.md
```

以下边界不在本任务包中重新讨论：

1. `.ikp` 不转换为 `.kpkg`。
2. KPM 管理 Kindle native Baga Platform；IKP Package Manager 管理 Baga App。
3. LifeBook/IKP 不直接依赖 KOReader / Kindle private API。
4. KOReader/koreader-base/FBInk 是 Kindle Platform internal adopted components。
5. Kindle Adapter 应尽量薄，优先包装成熟 Kindle 能力。
6. jailbreak route 属于 Client Installation Route DB，不属于 Adapter 或 Platform Core。
7. 不新增正式的 `Baga Runtime`、`Kindle Runtime`、`LifeBook Runtime` 等公共层。

## 7. 执行纪律

1. Batch 0 必须先核验当前仓库、上游源码、构建入口和文档是否漂移。
2. 不允许仅根据本任务包中的示意路径创建不存在的模块；先确认实际仓库结构。
3. 每个功能 Batch 必须形成 `RED → implementation → GREEN → evidence` 闭环。
4. 不允许把多个依赖 Batch 合并成一个不可定位的大补丁。
5. K0/K1 Gate 未通过前，不以 K2/K3 的临时代码绕开问题。
6. 不允许因为某语言“更快”或“更统一”重写已有成熟能力。
7. direct entry 发生具体 blocker 时必须记录日志/真机证据；没有证据不得切换 `.koplugin`。
8. 真机动作必须先确认备份、恢复路径和设备事实。
9. 实现证据推翻本任务包裁决时，先创建新的任务包版本，再继续涉及架构变化的代码。
10. 不另建平行 Task Design、Execution Prompt、handoff 或 scratch 目录；本目录就是当前实现上下文。
