# v1.1 总控：Kindle Platform 首轮实现范围、边界与执行纪律

**日期**: 2026-08-24  
**任务定位**: 本目录是 Baga Ink Platform Kindle Reference Port 的第一份完整实现任务包。  
**当前工程焦点**: 首台 stock 开发机 → Homebrew-ready + K0 + K1；K2–K7 保留完整后续路线。  
**首个真实设备**: Kindle（第十一代），firmware 5.16.3 (4110110057)，当前为 Amazon stock。  
**执行方式**: 未指定 Batch 时从 Batch 0 开始；当前 Batch Gate 全部通过后才能进入下一 Batch。

---

## 1. 本轮最终目标

本任务包覆盖从首台 stock Kindle 准备、可执行 Device Adapter Contract 到 Kindle Client 自动安装的完整路线，但首轮真正进入工程实施的是：

```text
Stock → Homebrew-ready
+
K0 executable Adapter Contract
+
K1 pinned KOReader/koreader-base KindleHF bring-up
```

第一条重大真机验收链仍是：

```text
real Kindle 11th Gen / 5.16.3
        ↓
WinterBreak2 → Homebrew-ready
        ↓
baga-launch
        ↓
pinned KOReader/koreader-base substrate
        ↓
Baga Ink Platform Core
        ↓
Kindle Device Adapter
        ↓
baga-probe.ikp
        ↓
visible UI + normalized input
        ↓

        ↓
sleep / wake
        ↓

```

`baga-probe.ikp` 是第一份真实 IKP。完整 LifeBook 不替代基础 Probe Gate。

## 2. 首台设备不再是假设 Homebrew-ready

此前任务包把首台设备写成：

```text
already jailbroken / Homebrew-ready
firmware >= 5.16.3
```

现在已有真实开发机，因此该假设废止。

当前设备事实固定为：

```text
product UI: Kindle（第十一代）
firmware: 5.16.3 (4110110057)
initial state: Amazon stock
jailbreak: no
Homebrew-ready: no
observed free storage before preparation: about 12.53 GB
expected native target: kindlehf
```

完整序列号、Wi-Fi MAC、Amazon account identity 不进入公开仓库或公开 evidence。

Stock → Homebrew-ready 的完整路线和 Gate 见 `20`。

## 3. Stock → Homebrew-ready 路线裁决

截至 2026-08-24，这台 5.16.3 开发机的默认路线固定为：

```text
Airplane Mode + OTA-risk preparation
        ↓
KindleModding Wizard route confirmation
        ↓
WinterBreak2
        ↓
modern post-jailbreak / hdnext state
        ↓
KPM available + OTA blocked
        ↓
Homebrew-ready
```

执行者不得临时改用其他 jailbreak。

WinterBreak2 失败时，只有满足 `20` 中定义的证据条件，且当前 KindleModding 文档仍保持相同建议，才允许回退 original WinterBreak。

SpringBreak / Sanctuary / Véra / AdBreak / Nosebleed 不作为本机 5.16.3 的默认路线。

## 6. 固定架构边界

必须服从：

```text
docs/zh-CN/standards/07_设备适配器规范.md
docs/zh-CN/standards/11_Kindle适配规范.md
docs/zh-CN/design/02_设备适配器可执行契约与SDK设计.md
docs/zh-CN/reference-apps/03_Kindle具体实现架构冻结.md
```

以下边界不在本任务包中重新讨论：

1. `.ikp` 不转换为 `.kpkg`。
2. KPM 管理 Kindle native Baga Platform；IKP Package Manager 管理 Baga App。
3. LifeBook/IKP 不直接依赖 KOReader / Kindle private API。
4. KOReader/koreader-base/FBInk 是 Kindle Platform internal adopted components。
5. Kindle Adapter 应尽量薄，优先包装成熟 Kindle 能力。
6. jailbreak route 属于 Client Installation Route DB；本轮手动 route 只是 Reference Development Device 准备，不改变该架构归属。
7. 不新增正式的 `Baga Runtime`、`Kindle Runtime`、`LifeBook Runtime` 等公共层。

## 9. 执行纪律

1. Batch 0 先保护 5.16.3，完成 WinterBreak2 route confirmation、jailbreak 与 Homebrew-ready Gate。
2. 在 Wi-Fi 前必须处理 OTA 风险；本机约有 12.53 GB 空闲空间，不能直接联网。
3. Batch 1 再核验当前仓库、上游源码、构建入口和文档是否漂移。
4. 不允许仅根据任务包中的示意路径创建不存在的模块；先确认实际仓库结构。
5. 每个功能 Batch 必须形成 `RED → implementation → GREEN → evidence` 闭环。
6. 不允许把多个依赖 Batch 合并成一个不可定位的大补丁。
7. Homebrew-ready Gate 未通过，不得用任何临时方式假装执行 K1/K2 真机代码。
8. 不允许因为某语言“更快”或“更统一”重写已有成熟能力。
9. direct entry 发生具体 blocker 时必须记录日志/真机证据；没有证据不得切换 `.koplugin`。
10. 真机动作必须先确认备份、恢复路径和设备事实。
11. factory reset / firmware upgrade / downgrade 都不是本轮正常执行动作。
12. 实现证据推翻本任务包裁决时，先修订任务包，再继续涉及架构变化的代码。
13. 不另建平行 Task Design、Execution Prompt、handoff 或 scratch 目录；本目录就是当前实现上下文。
