# v1.1 首台开发机 Stock → Homebrew-ready 路线与门禁

**职责**: 固定首台真实 Kindle 开发机从 Amazon stock 状态进入 Baga Kindle bring-up 所需 Homebrew-ready 状态的路线、风险控制、验证门禁与后续交接。本文是当前真机开工前的执行依据，不把 jailbreak 方法留给实现 Agent 临时选择。

---

## 1. 已确认的真实设备基线

首台 Reference Development Device 当前已确认：

```text
product UI: Kindle（第十一代）
firmware: 5.16.3 (4110110057)
initial state: Amazon stock firmware
jailbreak: no
Homebrew-ready: no
free storage observed before preparation: about 12.53 GB
```

公开仓库与公开测试证据不得记录完整序列号、Wi-Fi MAC、Amazon account identity 等设备唯一标识。需要 KindleModding Jailbreaking Wizard 校验型号时，只在本地临时使用设备序列号前 8 位，不写入 Git。

5.16.3 是 Kindle hard-float 工程边界。当前 Kindle SDK 文档将 firmware `>= 5.16.3` 映射到 `kindlehf` target，因此本机的预期 native target 固定为：

```text
kindlehf
```

正式 K1 artifact 仍须通过构建与真机证据确认，不能只引用版本号代替验证。

---

## 2. 当前 jailbreak 路线裁决

截至 2026-08-24，首选路线固定为：

```text
Amazon stock 5.16.3
        ↓
OTA-risk preparation
        ↓
WinterBreak2
        ↓
modern hdnext post-jailbreak state
        ↓
KPM available + OTA blocked
        ↓
Homebrew-ready development device
```

选择依据：

1. KindleModding 当前 WinterBreak2 指南明确适用于由 Jailbreaking Wizard 路由到该方法的受支持设备；
2. WinterBreak2 官方 troubleshooting 明确说明：firmware **低于 5.16.4** 时，如果 WinterBreak2 不工作，可回退到原始 WinterBreak；
3. 本机 firmware 为 **5.16.3**，正处于该边界内；
4. SpringBreak 当前面向更高版本/特定更新分支；Véra 当前面向更高 firmware；它们不作为这台 5.16.3 开发机的首选路线；
5. 原始 WinterBreak 需要 Amazon registration，因此仅作为 WinterBreak2 的已定义 fallback，不作为首选。

执行前必须用 KindleModding Jailbreaking Wizard 对**本地设备序列号前 8 位 + 5.16.3 + registration 状态**做一次 route confirmation：

```text
Wizard returns WinterBreak2
→ proceed

Wizard returns a different method / unsupported
→ STOP
→ 记录 upstream route drift
→ 修订本任务包后再执行
```

此确认步骤是防止上游兼容表发生变化，不是允许 AI 自行重新选型。

---

## 3. Fallback 裁决

WinterBreak2 在设备上失败时，不允许任意换 jailbreak。

唯一预定义 fallback：

```text
WinterBreak2 fails with reproducible evidence
+
firmware remains 5.16.3
+
Kindle can be registered
+
current KindleModding documentation still recommends fallback
        ↓
original WinterBreak
```

切换前必须保存：

```text
failure stage
browser behavior
visible error
files staged
firmware unchanged evidence
whether an OTA file appeared
whether any partial jailbreak marker exists
```

Sanctuary / SpringBreak / Véra / AdBreak / Nosebleed 等不得因为“更新”或“看起来更现代”而临时替换本路线。

---

## 4. 第一优先级：阻止自动升级

这台开发机当前有约 12.53 GB 空闲空间。任何 jailbreak 前 Wi-Fi 操作都存在自动下载 firmware 的风险，因此真正的第一步不是复制 jailbreak 文件，而是保护当前 5.16.3 状态。

在连接 Wi-Fi 前 MUST：

```text
[ ] 开启 Airplane Mode
[ ] 忘记/移除不必要的已保存 Wi-Fi，或确保不会自动连接
[ ] 通过电脑检查可见存储根目录
[ ] 删除任何已存在的 update*.bin / update.bin.tmp.partial 等 OTA 临时文件
[ ] 备份本机需要保留的书籍/笔记/开发资料
[ ] 手工填充可见存储，暂时只保留约 50–90 MB 可用空间
```

KindleModding 当前 OTA-prevention 指南特别指出：11th-generation 及更新设备采用 MTP，通用 filler script 不适用，因此此设备默认使用**手工 dummy/filler 文件**方式，不依赖旧 USB mass-storage filler script。

只有完成上述 Gate 后才临时打开 Wi-Fi 执行 WinterBreak2。

---

## 5. WinterBreak2 固定执行链

在 Wizard 确认路线且 OTA-risk Gate 完成后：

```text
1. 获取当前官方 WinterBreak2 release
2. 在电脑上解压
3. 将内容复制到 Kindle 可见存储根目录
4. 根目录确认至少存在：
   - jb.sh
   - patchedUks.sqsh
   - winterbreak2/
5. 安全弹出设备
6. 临时连接 Wi-Fi
7. 打开 Experimental Browser
8. 访问当前官方 WinterBreak2 页面
9. 触发 Jailbreak
10. 等待流程完成
11. 成功后立即重新进入 Airplane Mode
12. 检查是否出现 OTA/update 临时文件并按当前 upstream 指南处理
13. 执行 jailbreak/Homebrew-ready 验证
```

执行过程中禁止升级 firmware、factory reset、尝试 downgrade 或混用其他 jailbreak payload。

---

## 6. Homebrew-ready Gate

只有以下条件全部满足，K0/K1 真机开发才把设备状态记为 `Homebrew-ready`：

```text
[ ] firmware 仍为 5.16.3
[ ] `;log` 能确认 jailbreak state
[ ] modern post-jailbreak environment 已完成
[ ] KPM 可被调用
[ ] OTA blocking 已建立并经当前方法验证
[ ] 设备正常 reboot
[ ] Kindle Home/原生阅读基本功能正常
[ ] USB/MTP 开发传输仍可用
[ ] 无未知 update package 等待安装
```

当前 KindleModding 的 modern jailbreak “What’s Next” 文档说明 hdnext 路线会预装 KPM，并自动建立更新阻断。KPM 在这里是**开发设备已经具备的 Homebrew 基础设施**；K6 仍然负责 Baga Platform `.kpkg` 的正式产品化 packaging，不与这个事实冲突。

---

## 7. KPM 与 KOReader 的边界

设备进入 Homebrew-ready 后：

```text
KPM
→ 可以作为开发机现成的 package manager / launch infrastructure

Baga K1 pinned KOReader/koreader-base
→ 仍由 Baga 自己锁定、构建、验证
→ 不依赖用户通过 KPM 安装的任意 KOReader 版本
```

可选地通过 KPM 安装官方 KOReader 做环境对照测试，但该安装**不得成为 Baga Platform 的运行依赖或 K1 Gate**。

---

## 8. Stock → Homebrew-ready 完成后才进入的工作

Gate 通过后，真实施工序列为：

```text
Stock 5.16.3 device
        ↓
Batch 0: protect firmware + WinterBreak2 + Homebrew-ready evidence
        ↓
Batch 1: source/repository/current-state verification
        ↓
Batch 2: K0 executable Adapter Contract
        ↓
Batch 3: K1 upstream pin + kindlehf build baseline
        ↓
Batch 4: K1 direct Baga private entry
        ↓
first Baga-owned surface on real Kindle
```

之后才进入 K2 Kindle Device Adapter 和 K3 `baga-probe.ikp`。

---

## 9. 必须停止的条件

出现以下任一情况立即停止：

```text
firmware 已自动升级或版本不再是 5.16.3
Wizard 不再推荐 WinterBreak2
WinterBreak2 upstream 明确撤回该组合支持
无法将可用空间安全压到 OTA-protection 门槛
设备出现无法解释的 partial jailbreak state
设备无法正常 reboot / Home / USB-MTP
需要 factory reset 才能继续
需要用未验证 jailbreak 绕过当前 blocker
```

停止后保留证据并修订任务包，不允许为了赶进度把设备推进到未知状态。

---

## 10. 当前裁决

首台 Baga Kindle 开发机不再假设已经 Homebrew-ready。

当前真实起点固定为：

```text
Kindle 11th Gen / firmware 5.16.3 / stock
```

当前第一项真机工程工作固定为：

> **保护 5.16.3 不被 OTA 升级，并通过 WinterBreak2 将这台设备转换为可验证、可恢复的 Homebrew-ready `kindlehf` 开发机。**

只有该 Gate 通过，Baga Platform 的 K0/K1 真机 bring-up 才开始。
