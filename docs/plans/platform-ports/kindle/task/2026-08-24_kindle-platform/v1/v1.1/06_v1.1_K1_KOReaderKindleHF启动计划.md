# v1.1 K1：KOReader KindleHF 启动计划

**目标**: 在首台真实 Kindle（第十一代）/ firmware 5.16.3 完成 Batch 0 Stock → Homebrew-ready Gate 后，建立可重复的 Baga-controlled `kindlehf` development launch path。

```text
real Kindle 11th Gen / 5.16.3
→ verified Homebrew-ready
→ baga-launch
→ pinned KOReader/koreader-base substrate
→ direct Baga private entry
→ baga/bootstrap.lua
→ Baga-owned test surface
```

---

## 1. Preconditions

```text
Batch 0 Stock→Homebrew-ready Gate passed
real Kindle（第十一代）
firmware remains 5.16.3
jailbreak state verified
KPM available
OTA blocking verified
expected native target = kindlehf
known reboot/recovery path
verified USB/MTP development transfer path
```

K1 不负责自动 jailbreak。首台设备的手动 WinterBreak2 route 已由 `20` 固定；K7 才把经过验证的 route 自动化进 Client Route DB。

Kindle SDK 当前将 firmware `>=5.16.3` 映射到 `kindlehf`，但 K1 必须通过真实 build/artifact/device evidence 完成最终确认。

---

## 2. Scope

```text
K1-1  pin KOReader / koreader-base / FBInk candidate commits
K1-2  dependency/license/source-digest/patch manifest
K1-3  verify kindlehf native build baseline
K1-4  establish minimal baga-launch development entry
K1-5  add minimal direct Baga private entry patch
K1-6  implement baga/bootstrap.lua
K1-7  bootstrap diagnostics / crash log
K1-8  Baga-owned smoke surface
K1-9  at least one controlled input path
K1-10 cold start / exit / relaunch on the real 5.16.3 device
```

---

## 3. 默认启动裁决

K1 不重新比较两个同等候选。默认必须先实现：

```text
private KOReader bootstrap
→ direct Baga entry
→ Lua/LuaJIT Baga bootstrap
```

`.koplugin` 只在 direct path 有具体、可复现、已有证据的 blocker 时进入 fallback evaluation。

---

## 4. 实现语言

```text
KOReader environment integration → Lua/LuaJIT first
Baga bootstrap                 → Lua
launch wrapper                 → minimal shell/native mechanism
screen/input smoke             → KOReader existing Lua-facing knowledge
FBInk                          → existing C/native where required
```

不得在 K1 重新做 Rust/C/Lua 通用语言选型。

---

## 5. RED / Failure Evidence

先建立可观察失败点：

```text
upstream build cannot produce expected kindlehf artifact
artifact cannot execute on the prepared 5.16.3 device
launcher cannot locate pinned substrate
Baga private entry is absent
Baga surface not reached
input smoke not observed
exit/relaunch leaves stale state
```

每个失败必须能从日志阶段标记定位。

---

## 6. K1 Gate

首台真实设备必须证明：

```text
[ ] firmware remains 5.16.3
[ ] device remains Homebrew-ready / OTA-protected
[ ] pinned build 可重复
[ ] artifact/device evidence confirms kindlehf path
[ ] baga-launch 可进入 pinned substrate
[ ] direct private entry 无 FileManager/Plugin UI 产品暴露
[ ] Baga-owned test surface 可见
[ ] 至少一条输入路径可工作
[ ] clean exit
[ ] relaunch 成功
[ ] crash/last-stage diagnostics 可读取
```

此时还不要求真正 `.ikp`。

---

## 7. Write Scope

允许主要修改：

```text
pinned component integration area
Kindle build scripts/tooling
Baga bootstrap / launcher development code
tests/kindle/bringup/**
dependency/patch manifest
```

不要把完整 Device Adapter、IKP verifier、KPM 产品包或 Client 自动化塞入 K1。

首台开发机已有 KPM 只是 Homebrew foundation；K1 不以 `;kpm install koreader` 获得的用户版 KOReader 作为 Baga pinned substrate。
