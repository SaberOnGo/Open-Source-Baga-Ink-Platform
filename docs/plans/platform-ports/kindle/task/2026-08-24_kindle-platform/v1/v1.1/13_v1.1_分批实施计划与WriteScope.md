# v1.1 分批实施计划与 Write Scope

**职责**: 把首台 stock 开发机准备与 K0–K7 拆成可独立验证的 Batch，并明确每批允许写入范围。未指定 Batch 时从 Batch 0 开始。

---

## Batch 0 — 首台开发机 Stock → Homebrew-ready

**目标**: 把已确认的 Kindle（第十一代）/ firmware 5.16.3 从 Amazon stock 状态安全转换为可用于 Baga bring-up 的 Homebrew-ready 开发机。

必须完成：

```text
record non-sensitive device facts
Airplane Mode / OTA-risk preparation
backup required user/development data
remove visible pending OTA/update files
manual filler to about 50–90 MB free space
KindleModding Wizard route confirmation
WinterBreak2 staging + execution
post-jailbreak verification
KPM availability verification
OTA blocking verification
reboot / Kindle Home / USB-MTP smoke
```

固定 route、fallback 与停止条件见 `20`。

允许写：

```text
本任务包文档
local non-sensitive evidence records
ignored/private device backup assets
public evidence with unique device identifiers redacted
```

禁止：

```text
Baga functional implementation
firmware upgrade
factory reset as routine step
downgrade
unverified jailbreak switching
```

**Gate**: firmware 仍为 5.16.3，`;log` 确认 jailbreak，KPM 可调用，OTA blocking 已确认，设备可正常 reboot/Home/USB-MTP。

## 跨 Batch 禁止事项

1. Batch 0 未通过不得进行任何需要 Homebrew 的真机 Baga bring-up。
2. Batch 0 不允许为了省事升级 firmware、factory reset、downgrade 或随机切换 jailbreak。
3. Batch 1 未完成不得用猜测路径开始功能代码。
4. 不允许 Batch 3 为了省事顺便实现完整 K2 Adapter。
5. 不允许 Batch 4 为了展示 UI 直接在 KOReader FileManager 中做产品入口。
6. 不允许 Batch 5 让 App 直接依赖 KOReader private object。
7. 不允许 Batch 6 用未签名开发 loader 证明 K4 已完成。
8. 不允许 Batch 9 把 jailbreak route 固化到 Platform package。
9. 不允许 Batch 10 修改 Device Adapter Contract 来适配 Client route。

## 每个 Batch 的标准闭环

```text
read governing docs/source
→ verify prerequisites
→ write/update batch plan if needed
→ expected-fail RED
→ implementation / device operation
→ expected-pass GREEN
→ device/manual evidence where required
→ update checklist/result
→ only then next Batch
```

Batch 0 的 RED/GREEN 是设备状态 Gate：RED = stock/not Homebrew-ready；GREEN = same firmware + verified jailbreak/KPM/OTA-block state。
