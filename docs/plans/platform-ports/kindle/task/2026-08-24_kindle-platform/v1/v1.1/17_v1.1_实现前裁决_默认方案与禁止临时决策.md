# v1.1 实现前裁决：默认方案与禁止临时决策

**职责**: 收敛 v1.1 在交给实现 Agent 前仍可能产生歧义的选择。本文与 `00`、`20` 是本任务包的当前裁决入口；实现时不重新把下列项目当成开放问题。

---

## 1. 当前默认裁决表

| 项目 | v1.1 裁决 | 允许改变的条件 |
|---|---|---|
| 首个设备 | Kindle（第十一代），firmware 5.16.3，当前 stock | 真实设备事实变化 |
| 首个设备目标状态 | Homebrew-ready `kindlehf` development device | 当前 upstream route/support 变化 |
| 首选 jailbreak | WinterBreak2，执行前由 KindleModding Wizard 对本机 route 做 confirmation | Wizard/upstream 明确返回不同结果 |
| jailbreak fallback | original WinterBreak only，且满足 `20` 的证据/registration Gate | 当前 upstream recommendation 改变 |
| OTA 防护 | Airplane Mode + 删除 pending OTA + 11th Gen 手工 filler 至约 50–90 MB 空闲 | 上游 OTA 机制/指南有明确变化 |
| 第一工程重点 | Stock→Homebrew-ready + K0 + K1 | 对应 Gate 通过后进入后续 Batch |
| 第一真实 IKP | `baga-probe.ikp` | 不以 LifeBook 替代 |
| Adapter Contract 语言 | language-neutral | 不写入实现语言限制 |
| Kindle glue | Lua/LuaJIT first | ABI/crash/performance/security 等证据 |
| FBInk | 保持现有 C/native | 上游事实变化 |
| KOReader device/input/lifecycle | 直接包装成熟实现 | 具体能力缺失并有证据 |
| K1 entry | direct Baga private entry | 可复现 blocker |
| `.koplugin` | fallback only | direct entry blocker 已记录 |
| KOReader 分发 | Baga pinned private component set | 后续显式架构修订 |

| IKP package manager | Platform App package manager | 不转换成 KPM |
| jailbreak routes | 架构上属于 K7 Client Route DB；本轮手动验证首台设备 route | 不进入 Adapter/Core |
| Reader | K5 复用 ReaderUI/CREngine/MuPDF | 不自行重写 reader engine |
| compatibility expansion | `kindlehf → kindlepw2 → kindle → kindle-legacy` 按证据扩展 | 真实设备/优先级证据调整 |

## 2. 实现 Agent 不得临时决定

以下行为属于方案变化，不能在单次 coding/device session 中自行完成：

```text
在 5.16.3 首台设备上跳过 WinterBreak2，任意换 Sanctuary/SpringBreak/Véra/AdBreak/Nosebleed
在未完成 OTA 保护时直接让 stock 设备联网
把 factory reset / firmware upgrade / downgrade 当成普通准备步骤
把 direct entry 改回普通 KOReader plugin
把 Kindle Adapter 主体从 Lua glue 改成重新实现的 Rust/C stack
新增 Adapter daemon/RPC
让 IKP 直接依赖 KOReader API
把 KPM 与 IKP package manager 合并
把 jailbreak exploit 固化为 Platform dependency
把 ReaderUI 塞入 Device Adapter root
跳过 Probe，直接用 LifeBook 宣称 Platform bring-up 完成
对未知 firmware 猜测 Stable compatibility
```

需要改变时必须先写 evidence，并修订 Task Package。

## 3. 可以在实现中局部裁量的事项

以下属于普通实现细节，只要不改变上位语义，可以在当前 Batch 内选择：

```text
private CLI flag 的具体名称
Lua module 的内部文件拆分
日志字段的非公共内部格式
测试 helper 名称
小型函数/类型命名
构建脚本内部实现
同一成熟 backend 内的非架构性调用方式
```

但仍须满足 Write Scope、tests、public API/identifier language rules。

## 4. 首台 jailbreak route 失败的裁决流程

WinterBreak2 不通过时：

```text
1. 立即保持/恢复 Airplane Mode
2. 确认 firmware 仍为 5.16.3
3. 保存失败 stage / browser behavior / visible error / staged files
4. 检查是否出现 pending OTA/update file
5. 检查是否存在 partial jailbreak state
6. 重新核对 KindleModding current WinterBreak2 troubleshooting / Wizard
7. 只有 `20` 的 fallback 条件全满足，才允许 original WinterBreak
8. 其他 jailbreak 不得临时尝试
```

如果需要第三种 route，先修订任务包，不在现场继续试错。

---

## 5. direct entry 失败的裁决流程

如果 direct entry 不通过：

```text
1. 保存 build/log/device evidence
2. 确认 blocker 位于 entry 技术而非普通 bug
3. 记录无法通过小 patch 修复的原因
4. 比较 `.koplugin` fallback 是否消除该 blocker
5. 更新 03/06/13/14/17/19
6. 创建新的 v1.x
7. 再进入 fallback implementation
```

不得因为 `.koplugin` 更容易做 PoC 就绕过默认方案。

---

## 6. Lua-first 失败的裁决流程

只有以下情况才考虑某个 subsystem 改用/增加 native：

```text
KOReader Lua surface 根本不提供所需能力
目标 ABI 的 binding 不可用
可复现性能瓶颈超过明确 Gate
生命周期/线程/安全限制无法通过 Lua glue 满足
成熟 native API 明显是更短且更稳定的接入层
```

即使使用 native，也优先 narrow binding，不重新实现整个 Kindle stack。

---

## 7. Batch 自动推进规则

实现 Agent 可以在同一工作目标中按 Batch 自动推进，但只有当前 Gate 全部通过时才能进入下一 Batch。

当前顺序固定：

```text
Batch 0  Stock 5.16.3 → Homebrew-ready
Batch 1  source/current-state verification
Batch 2  K0
Batch 3  K1 build baseline
Batch 4  K1 direct entry
...
```

必须暂停的情况：

```text
firmware 不再是 5.16.3
Wizard route 与 `20` 冲突
设备无法可靠恢复
出现用户数据风险
Task docs 与当前源码冲突
需要上位 Standard/Freeze 变更
RED 测试无法合理建立
GREEN 无法达到且原因不明确
需要改变本文固定裁决
```

## 8. v1.1 开工条件

真正的开工前置 Gate 分两层。

### Batch 0 前

```text
[ ] 设备仍为 stock 5.16.3
[ ] Airplane Mode 已开启
[ ] 待保留数据可备份
[ ] OTA-risk preparation 可以执行
[ ] 本地可以运行 KindleModding Wizard route confirmation
```

### Batch 1/2 前

```text
[ ] Batch 0 Homebrew-ready Gate 全通过
[ ] firmware 仍为 5.16.3
[ ] KPM 可调用
[ ] OTA block 已确认
[ ] 上游源码路径已核验
[ ] current repo gap 已核验
[ ] test/evidence location 已确认
[ ] dependency/license initial manifest 已确认
[ ] direct-entry insertion point 已找到
[ ] kindlehf build target 来源已找到
[ ] 没有未解决的文档冲突
```

**最终裁决**: v1.1 不再假设开发 Kindle 已经越狱，也不把 jailbreak、语言或 entry 架构选型留给执行阶段。当前执行从保护 stock 5.16.3 和 WinterBreak2 开始；证据推翻方案时才回到任务设计层修改。
