# v1.1 当前仓库现状与 Kindle 实现差距清单

**职责**: 记录进入 Kindle 实现前仓库已有资产、首台真实开发机状态与仍缺失的工程能力，防止实现 Agent 把规划文档或设备假设误当成已完成实现。

---

## 2. 首台真实开发机状态

当前已有一台专门用于 Reference Port bring-up 的真实设备：

```text
product UI: Kindle（第十一代）
firmware: 5.16.3 (4110110057)
state: Amazon stock
jailbreak: no
Homebrew-ready: no
observed free storage: about 12.53 GB
expected native target: kindlehf
```

因此当前最先缺失的不是 Adapter 代码，而是：

```text
OTA-safe preparation
WinterBreak2 route confirmation / execution
verified jailbreak state
KPM availability
OTA blocking evidence
reboot/Home/USB-MTP smoke
```

完整 route 与 Gate 见 `20`。

公开仓库不得记录该设备完整序列号、Wi-Fi MAC 或 Amazon account identity。

```text
spec/adapter/                 # Adapter machine contract

platform/core/                # minimal Platform Core

platform/components|vendor/   # pinned KOReader/koreader-base/FBInk integration

client/kindle/                # later K7
```

Batch 1 必须以当前 `main` 实际文件树复核本表；若已有其他工作合入，应更新本表后再实施。

## 8. K4–K7 差距摘要

| Milestone | 主要缺口 |
|---|---|
| K4 | device verifier integration、staging、immutable release、atomic activation、rollback |
| K5 | `baga.reader` 到 ReaderUI/CREngine/MuPDF 的内部 bridge |
| K6 | `.kpkg`、health check、install/update/uninstall、sh_integration Home Entry |
| K7 | USB/device detection、Route DB、state resolver、jailbreak/KPM bootstrap automation、IKP transfer/result handshake |

Batch 0 手动验证的首台 5.16.3 WinterBreak2 route 将来是 K7 Route DB 的真实 evidence 来源之一，但不会进入 Adapter 或 Platform Core。
