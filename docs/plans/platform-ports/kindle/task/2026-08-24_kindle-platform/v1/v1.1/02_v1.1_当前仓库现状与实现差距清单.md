# v1.1 当前仓库现状与 Kindle 实现差距清单

**职责**: 记录进入 Kindle 实现前仓库已有资产与仍缺失的工程能力，防止实现 Agent 把规划文档误当成已存在代码。

---

## 1. 当前已有的权威资产

仓库已经具备：

```text
Device Adapter Standard
Kindle Adapter Standard
Compatibility Standard / Test Suite
IKP / API / Permission / UI 等 Standards
Device Adapter executable-contract Approved Design
Kindle Implementation Architecture Freeze
IKP/signing/update executable specification 与 reference implementation 基础
Kindle Implementation Master Plan
```

这些文档已经解决主要架构边界，但不等于 Kindle Platform 已实现。

---

## 2. 当前缺失的 Kindle 实现主体

在 v1.1 开工点，以下目标代码仍需要实际建立或按仓库最新状态核验：

```text
spec/adapter/                 # Adapter machine contract
sdk/adapter/                  # generated bindings / mock
platform/core/                # minimal Platform Core
platform/lua/                 # embedded Lua/Baga bootstrap
platform/adapters/kindle/     # Kindle Reference Adapter
platform/components|vendor/   # pinned KOReader/koreader-base/FBInk integration
apps/probe/                   # baga-probe.ikp source/assets
client/kindle/                # later K7
```

Batch 0 必须以当前 `main` 实际文件树复核本表；若已有其他工作合入，应更新本表后再实施。

## 6. K3 差距

尚需建立最小 Platform App 闭环：

```text
App Registry
App Context
Embedded Lua Host / Baga Lua Profile minimum
Lifecycle dispatcher
Adapter dispatch
permission/sandbox skeleton

baga.storage

developer-mode IKP loader
baga-probe.ikp
persistent counter + sleep/wake validation
```

这是第一次证明 Universal IKP App 能在真实 Kindle Platform 上运行。

---

## 7. K4–K7 差距摘要

| Milestone | 主要缺口 |
|---|---|
| K4 | device verifier integration、staging、immutable release、atomic activation、rollback |
| K5 | `baga.reader` 到 ReaderUI/CREngine/MuPDF 的内部 bridge |
| K6 | `.kpkg`、health check、install/update/uninstall、sh_integration Home Entry |
| K7 | USB/device detection、Route DB、state resolver、KPM bootstrap、IKP transfer/result handshake |

这些规划已存在，但 K0–K3 Gate 未完成前不得把后续模块的临时代码作为基础链替代方案。

---

## 8. 文档结构差距已经在 v1.1 修正

旧计划结构把 K0–K7 分散到多个 `TASK-NNNN/vNNN`，并另建 `execution-prompts/` 镜像树。该结构增加了实现者重建上下文的成本。

v1.1 起，当前 Kindle 工作统一由本目录平铺承载：

```text
00–19
```

旧分散任务目录不再作为当前实现来源。
