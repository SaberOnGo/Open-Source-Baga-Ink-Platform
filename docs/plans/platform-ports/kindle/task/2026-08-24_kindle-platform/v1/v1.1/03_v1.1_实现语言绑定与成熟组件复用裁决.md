# v1.1 实现语言、Binding 与成熟组件复用裁决

**职责**: 固定 Kindle K0–K3 的语言/绑定默认方案。后续实现不得在每个 Batch 中重新进行通用语言选型。

---

## 1. Contract 不限制实现语言

Baga Device Adapter Contract 冻结：

```text
interfaces / semantics
capabilities
errors
normalized events
lifecycle
compatibility requirements
tests
```

不冻结：

```text
Rust / C / Kotlin / Lua / Zig / other implementation language
```

官方 generated binding 只是工具链支持，不是实现语言白名单。Adapter 是否合格由 Contract Tests / BICTS 与真实设备证据判断。

---

## 2. 语言/绑定选择顺序

需要实现新的 subsystem 时，按以下优先级判断：

```text
1. 成熟能力已经存在于哪一层，能否直接包装
2. 对目标 model / firmware / ABI 的兼容性与验证程度
3. 是否能减少 glue / FFI / IPC / data conversion
4. 维护、调试和跟随 pinned upstream 升级的成本
5. 启动时间、内存和包体积
6. 实测性能
7. 安全/内存安全要求
```

“某语言更快”“某语言更底层”“统一语言更整齐”本身不能成为重写成熟模块的理由。

---

## 3. Kindle v1.1 默认矩阵

| Area | v1.1 默认 | 规则 |
|---|---|---|
| KOReader bootstrap / Baga bootstrap | **Lua/LuaJIT first** | 直接复用 KOReader 已有环境 |
| Adapter common glue | **Lua first** | identity/capability/profile/quirk/error/event/self-test 做薄 normalization |
| DisplayAdapter | **Lua wrapper around KOReader first** | profile 需要时接现有 FBInk C/native；不重写 framebuffer |
| InputAdapter | **Lua wrapper around KOReader** | 不重写 evdev/touch calibration，除非精确 quirk 证据 |
| LifecycleAdapter | **Lua wrapper first** | 复用 KOReader/Kindle/Homebrew events |
| PowerAdapter | **Lua wrapper first** | 需要 native 时只加窄 binding，不建立新 daemon |
| Frontlight / device network state | **Lua wrapper first** | 复用成熟机制；HTTP/TLS 不在 Adapter 重写 |
| Storage policy/glue | **Lua first** | 成熟 SQLite/native I/O 继续复用；Baga 负责 containment semantics |
| KOReader UI / Reader | **existing Lua/LuaJIT** | 属于 Platform UI/Reader implementation |
| FBInk | **existing C/native** | 不改写成 Lua |
| IKP verifier / crypto | **existing verified native/Rust/C core** | 不因为 Kindle 主 glue 用 Lua 而重写 verifier |

允许一个 Adapter 使用多种语言。

## 4. Codegen 与实现语言分离

`spec/adapter/*` 是语言无关的语义源。

当前 Approved Design 的首批 generated targets：

```text
Rust
C
Kotlin
```

v1.1 的固定解释：

1. 当前没有通用 generated Lua SDK，不影响 Kindle Adapter 使用 Lua。
2. 新增通用 Lua codegen 不作为 K0/K1 前置条件。
3. Kindle Lua glue 仍必须符合同一 IDL 语义并通过同一 Contract Tests。
4. 如果未来把 Lua 升为正式 first-party generated target，应在 Approved Design 中单独增加，不与 Kindle bring-up 绑死。

---

## 5. K1 启动方案固定为 direct entry

默认链：

```text
baga-launch
→ pinned private KOReader bootstrap
→ direct Baga private entry
→ baga/bootstrap.lua
→ Baga-owned surface / Platform bootstrap
```

可使用类似 `--baga-app <app-id>` 的 private argument；参数名属于内部实现细节。

`.koplugin` 不是并列默认方案，只在以下情况作为 fallback：

```text
direct entry 有可复现 build/launch blocker
FileManager/UI 暴露无法消除
lifecycle/shutdown 无法可靠接管
local patch maintenance cost 明显不可接受
crash recovery 无法形成稳定链
```

必须有源码/日志/真机证据。

---

## 6. 禁止为了语言统一重写

禁止：

```text
Rust/C 重写 KOReader 已成熟 Kindle input/device/lifecycle knowledge
Lua 重写 FBInk
为了统一语言增加多层 FFI
把 KOReader Lua object 暴露为公共 Baga API
LifeBook/IKP 直接 require KOReader private module
把源码语言写进 Device Adapter Contract
```

目标始终是：

```text
mature capability
→ thinnest safe binding/glue
→ Baga semantic contract
```

---

## 7. 允许偏离的证据

只有以下证据可以触发更换语言/backend：

```text
目标 ABI 无法构建或加载
目标 firmware API 不可用
可复现 crash / lifecycle failure
profiling 证明当前路径形成瓶颈
明确内存/启动 Gate 无法满足
binding 存在不可接受安全风险
upstream 结构变化导致原接入层不再稳定
```

偏离流程：

```text
evidence
→ 更新本任务包并形成新的 vN.M
→ 修改 affected Batch / tests / recovery
→ 再进入实现
```

单次编码过程中不得静默更换总体方案。
