# v1.1 K4：IKP 安装激活与设备验证计划

**目标**: 把 K3 的开发模式 IKP 启动升级为可验证、可恢复的设备端 App 安装链。

```text
IKP input
→ strict package validation
→ canonical/signature verification
→ staging
→ immutable release
→ atomic activation
→ health/probation
→ active or rollback
```

---

## 1. Dependency Gate

前置：

```text
K3 developer-mode Probe chain stable
+
repository executable IKP/signing verifier has stable shared vectors
```

Kindle 不实现第二套 canonicalization/signature 语义。

---

## 2. Scope

```text
IKP package reader integration
strict manifest/package validation
device verifier integration
staging layout
immutable release layout
package/data separation
atomic active-release state
health/probation result
last-known-good rollback
negative tests
shared vectors with reference verifier
install/update/rollback BICTS subset
```

---

## 3. Data Safety

必须保持：

```text
App package release
!=
App user data
```

update/rollback 不得通过删除 App data 来恢复 package。

---

## 4. RED Tests

至少覆盖：

```text
unsigned IKP rejected
wrong hash rejected
non-canonical/invalid manifest rejected
partial staging cannot become active
failed health check cannot remain active
rollback preserves App data
Kindle verifier result differs from reference vector -> test failure
```

---

## 5. K4 Gate

```text
[ ] invalid IKP cannot activate
[ ] verified IKP stages before activation
[ ] activation is atomic/recoverable
[ ] last-known-good rollback works
[ ] rollback preserves data
[ ] reference/device verifier agree on shared vectors
[ ] Platform native update and IKP App update remain separate transactions
```

---

## 6. Out of Scope

```text
Baga Market discovery UI
Client USB transfer
KPM Platform update
jailbreak routes
```
