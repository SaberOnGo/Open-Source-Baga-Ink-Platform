# v1.1 真机验证、证据、备份与恢复计划

**职责**: 规定 Kindle 真机操作前必须记录什么、备份什么、如何恢复以及怎样保存可以复核的证据。首台设备当前为 stock Kindle（第十一代）/ 5.16.3，因此本文件从 jailbreak 前的设备保护开始，而不是从已 Homebrew-ready 状态开始。

---

## 1. 首台设备事实

首台 Reference Development Device 当前公开可记录事实：

```text
product UI: Kindle（第十一代）
firmware: 5.16.3 (4110110057)
initial state: Amazon stock
Homebrew-ready: no
observed free storage before preparation: about 12.53 GB
expected native target: kindlehf
```

每次真机 run 继续记录：

```text
device model / model id when safely available
firmware version
native target
jailbreak/Homebrew-ready state
KPM state
Platform build/commit
pinned KOReader/koreader-base/FBInk commits
local patch set id/digest
IKP/app build digest when relevant
```

不得把完整序列号、Wi-Fi MAC、Amazon account identity 写入公开 Git、Issue、PR、截图或 evidence。需要 jailbreak route wizard 时只在本地临时使用序列号前 8 位。

## 2. Batch 0：Stock → Homebrew-ready 前备份与 OTA 保护

任何 Wi-Fi jailbreak 操作前必须完成：

```text
[ ] Airplane Mode 已开启
[ ] 不会自动连接已保存 Wi-Fi
[ ] 当前 firmware 重新确认仍为 5.16.3
[ ] Kindle 可见存储中待保留书籍/笔记/开发资料已备份
[ ] 检查并移除可见的 update*.bin / update.bin.tmp.partial 等 OTA 文件
[ ] 当前约 12.53 GB 空闲空间已通过手工 filler 压到约 50–90 MB
[ ] 本地记录 KindleModding Wizard route confirmation 结果
[ ] WinterBreak2 release/source 已从当前官方上游确认
[ ] 已知设备 reboot 与 USB/MTP 恢复路径
```

11th-generation 及更新 Kindle 的当前 OTA-prevention 指南不依赖旧 mass-storage filler script；此开发机按当前上游建议使用手工 dummy/filler 文件。

## 3. Batch 0 允许与禁止的恢复动作

允许：

```text
reboot
重新进入 Airplane Mode
移除本轮复制的 jailbreak/filler 开发文件
恢复本轮覆盖的普通可见存储文件
在明确 upstream 指南下重试同一 WinterBreak2 route
```

未经新裁决禁止：

```text
factory reset
firmware update
downgrade
随机更换 jailbreak 方法
跨方法混用 payload
擦除用户 documents 作为“恢复”
```

如果 WinterBreak2 失败但设备仍为 stock 5.16.3，按 `20` 的 fallback Gate 判断是否允许 original WinterBreak；不得由实现 Agent临时选择其他 exploit。

## 4. Homebrew-ready 验收证据

Batch 0 的 GREEN evidence 至少包含：

```text
firmware remains 5.16.3
`;log` jailbreak-state result
KPM invocation result
OTA-block state evidence
normal reboot result
Kindle Home smoke
native reading/basic system smoke
USB/MTP transfer smoke
no pending unknown update package
```

Homebrew-ready 不是“屏幕上出现过 jailbreak 文本”就算完成。

## 5. 后续真机前备份

进入 K1/K2/K3 后，每批至少确认：

```text
[ ] 本 Batch 会覆盖的开发文件已备份
[ ] 原有 Baga Platform/KOReader test area 可恢复
[ ] Kindle 用户书籍/笔记不在写范围
[ ] App data 与 package release 分离
[ ] 已知 reboot/recovery path 可执行
[ ] USB/MTP transfer path 可用
[ ] firmware 仍为 5.16.3 或当前 Task 明确批准的版本
```

任何 install/update/uninstall 测试都不得用恢复出厂作为正常回滚策略。

## 8. K1 真机最小序列

只有 Batch 0 Homebrew-ready Gate 通过后才执行：

```text
1. record device facts
2. verify firmware remains expected
3. verify recovery path
4. deploy pinned development substrate
5. launch baseline
6. invoke baga-launch
7. confirm direct Baga private entry
8. confirm Baga-owned surface
9. trigger one input path
10. clean exit
11. relaunch
12. capture logs/evidence
13. restore test changes when required
```

如果设备卡在启动、screen ownership 或 lifecycle 异常状态，停止后续 Batch，先完成恢复和 blocker 记录。

## 11. 什么时候停止自动推进

出现以下任一情况必须停止当前 Batch：

```text
firmware/model 与记录不符
5.16.3 在 Batch 0 前被升级
Wizard route 与 `20` 不一致
设备无法可靠恢复
出现用户数据风险
未知 native target
screen/input/power 行为与 profile 冲突
crash 无法定位 stage
需要 factory reset 才能继续
需要改变冻结架构或当前任务包裁决
```

停止后先记录证据和恢复结果，再决定是否修订任务包。
