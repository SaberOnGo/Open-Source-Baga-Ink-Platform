# v1.1 真机验证、证据、备份与恢复计划

**职责**: 规定 Kindle 真机操作前必须记录什么、备份什么、如何恢复以及怎样保存可以复核的证据。

---

## 1. 首台设备事实

每次真机 run 必须记录：

```text
device model / model id
firmware version
native target
Homebrew-ready state
KPM state when relevant
Platform build/commit
pinned KOReader/koreader-base/FBInk commits
local patch set id/digest
IKP/app build digest when relevant
```

不得用“现代 Paperwhite”“类似 kindlehf”代替精确设备事实。

---

## 2. 真机前备份

操作前至少确认：

```text
[ ] 本 Batch 会覆盖的开发文件已备份
[ ] 原有 Baga Platform/KOReader test area 可恢复
[ ] Kindle 用户书籍/笔记不在写范围
[ ] App data 与 package release 分离
[ ] 已知 reboot/recovery path 可执行
[ ] USB/transfer path 可用
```

任何 install/update/uninstall 测试都不得用恢复出厂作为正常回滚策略。

---

## 3. 证据目录建议

实现仓库可按实际测试资产布局建立：

```text
tests/evidence/kindle/<date>/<batch>/
├── red/
├── green/
├── device/
└── summary.md
```

如果仓库已有统一 evidence 规范，以现有规范为准；Batch 0 负责把本文路径更新成真实路径。

## 5. K1 真机最小序列

```text
1. record device facts
2. verify recovery path
3. deploy pinned development substrate
4. launch baseline
5. invoke baga-launch
6. confirm direct Baga private entry
7. confirm Baga-owned surface
8. trigger one input path
9. clean exit
10. relaunch
11. capture logs/evidence
12. restore test changes when required
```

如果设备卡在启动、screen ownership 或 lifecycle 异常状态，停止后续 Batch，先完成恢复和 blocker 记录。

## 7. K3 Probe 真机专项

```text
launch probe
counter 1 → 2
exit/relaunch retains expected stored state
sleep/wake retains state
multiple repeated input operations
log contains no direct App access to KOReader private API
```

这是第一条完整 Baga Platform device evidence。

---

## 8. K4/K6 数据保护专项

必须设计中断/失败场景：

```text
partial staging
invalid package
failed health check
Platform update interruption
rollback
uninstall
```

验收核心：

```text
Kindle books unaffected
Kindle notes unaffected
Baga App data preserved according to policy
last-known-good recoverable
```

---

## 9. 什么时候停止自动推进

出现以下任一情况必须停止当前 Batch：

```text
设备无法可靠恢复
出现用户数据风险
firmware/model 与预期不符
未知 native target
screen/input/power 行为与 profile 冲突
crash 无法定位 stage
需要改变冻结架构或当前任务包裁决
```

停止后先记录证据和恢复结果，再决定是否建立新的任务包版本。
