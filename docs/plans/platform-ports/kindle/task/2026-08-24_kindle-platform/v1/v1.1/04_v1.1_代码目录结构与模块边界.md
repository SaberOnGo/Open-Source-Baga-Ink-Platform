# v1.1 代码目录结构与模块边界

**职责**: 固定 K0–K7 实现的职责边界和目标目录，防止 bring-up 期间为了方便把 Reader、Adapter、package manager、Client route 混在一起。

---

```text

    ├── contract.yaml
    ├── types.yaml
    ├── descriptor.yaml
    ├── events.yaml
    ├── errors.yaml
    ├── subsystems/
    │   ├── display.yaml
    │   ├── input.yaml
    │   ├── storage.yaml
    │   ├── lifecycle.yaml
    │   └── power.yaml
    └── frozen/

sdk/
└── adapter/
    ├── generated/
    └── mock/

tools/
└── baga-adapter-codegen/

tests/
├── adapter_contract/
├── adapter_mock/
└── kindle/

platform/
├── core/
├── lua/
├── adapters/
│   ├── mock/
│   └── kindle/
│       ├── common/
│       ├── display/
│       ├── input/
│       ├── storage/
│       ├── lifecycle/
```

实际目录可以根据当前源码微调，但职责分层不得改变。

---

## 2. `spec/adapter/`

只保存语言无关、跨设备稳定的 Device Adapter Contract machine source：

```text
interfaces
methods
types/enums
required/optional semantics
errors
events
version metadata
```

不得放：

```text
Kindle waveform
KOReader Lua object
Android Context
BOOX class
specific build toolchain
```

---

## 3. `platform/adapters/kindle/`

只负责：

```text
factory/probe
DeviceDescriptor
CapabilitySnapshot
profile/quirk selection
Display/Input/Storage/Lifecycle/Power normalization
optional Network/Light/Library bridge
error/event normalization
self-test/diagnostics
```

不负责：

```text
ReaderUI / CREngine / MuPDF
KPM / MRPI
jailbreak routes
Kindle Home product entry
Client USB detection
IKP signature algorithm
```

---

## 4. KOReader / FBInk 边界

KOReader/koreader-base/FBInk 是 Platform adopted components。

```text
baga.ui
→ Platform UI implementation
→ KOReader UIManager/widgets
→ Kindle Adapter Display/Input
```

```text
baga.reader
→ Platform Reader implementation
→ ReaderUI / CREngine / MuPDF
→ Kindle Adapter
```

LifeBook/IKP 不直接调用这些 private modules。

---

## 5. Platform Core

K3 的最小 Platform Core 只负责：

```text
App Registry / App Context
Embedded Lua Host
lifecycle dispatch
Adapter dispatch
permission/sandbox skeleton
baga.* API minimum
IKP developer-mode load
```

不能把 KOReader 直接变成 Platform Core 的公共 API。

---

## 6. 两套 Package Manager

严格分离：

```text
KPM
→ Kindle native Baga Platform package
→ baga-platform_<version>_<target>.kpkg
```

```text
IKP Package Manager
→ Universal Baga Apps
→ lifebook.ikp / probe.ikp / other apps
```

不存在 `.ikp → .kpkg` 转换。

---

## 7. Client Route DB

K7 的 Client 负责：

```text
USB/device detection
model/firmware/current-state collection
route resolution
Homebrew/KPM state handling
Platform ensure/install
IKP transfer/result handshake
```

WinterBreak/SpringBreak/Sanctuary/Véra 等只出现在 route records，不进入 Adapter/Platform Contract。

---

## 8. Write Scope 纪律

每个 Batch 的允许写入模块见 `13`。当实际仓库结构与本文示意不同：

1. 先在 Batch 0 记录真实路径；
2. 更新本文；
3. 再进入功能代码。

不得为了满足示意目录而机械移动无关模块。
